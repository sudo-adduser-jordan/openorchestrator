Open Agents keeps its durable state under `~/.open-agents`. The daemon stores projects, sessions, pull-request facts, notifications, and typed project configuration in SQLite under `~/.open-agents/data`; `~/.open-agents/running.json` lets the desktop app and CLI find the running daemon.

The desktop app is the normal place to add projects and change settings. The CLI talks to the same daemon API when you need a scriptable path.

## Add a project

In the desktop app, choose **Add project** and select a local repository. From the CLI:

```bash
open-agents project add --path /absolute/path/to/repo
```

To set the default agents while registering the project:

```bash
open-agents project add --path /absolute/path/to/repo \
  --worker-agent opencode \
  --manager-agent opencode
```

Open Agents also supports workspace projects, which contain a root repository and direct child repositories:

```bash
open-agents project add --path /absolute/path/to/workspace --as-workspace
```

Fresh installations include a Scratch project for work that does not need Git. Scratch sessions use Open Agents-managed directories and do not support branches or pull-request claims.

## Inspect and update configuration

```bash
open-agents project ls
open-agents project get <project-id>
open-agents project set-config <project-id> --worker-agent opencode
```

`set-config` replaces the stored project configuration. Prefer project settings in the desktop app for interactive edits, or first inspect `open-agents project get <project-id> --json` before replacing configuration in a script. `--config-json` accepts a JSON object string, not a filename.

Current project configuration is typed. It covers the base branch, session prefix, environment variables, symlinks, setup commands, worker and manager agents, agent options, project rules, reviewer agents, tracker intake, and container cleanup. Unknown fields are rejected instead of being silently ignored.

See [Projects](/docs/configuration/projects) for the current field reference.

## Daemon environment

The primary daemon listener is always loopback-only and unauthenticated. Its bind host is not configurable. Useful environment variables include:

| Variable | Default | Purpose |
| --- | --- | --- |
| `OPEN_AGENTS_PORT` | `3001` | REST, events, terminal mux, health, and control port |
| `OPEN_AGENTS_DATA_DIR` | `~/.open-agents/data` | Durable daemon data |
| `OPEN_AGENTS_RUN_FILE` | `~/.open-agents/running.json` | Daemon discovery file |
| `OPEN_AGENTS_REQUEST_TIMEOUT` | `60s` | REST request timeout |
| `OPEN_AGENTS_SHUTDOWN_TIMEOUT` | `10s` | Graceful shutdown deadline |
| `OPEN_AGENTS_ALLOWED_ORIGINS` | packaged desktop origin | Additional trusted browser origins |

Do not set `HOST=0.0.0.0` or proxy the primary daemon to a network.

## Chat and Terminal UI defaults

Every session commits to one interface at a time:

- **Chat** uses a structured, runtime-less provider controller with durable messages, activities, approvals, and usage.
- **Terminal UI** runs the agent's native terminal interface through Open Agents's terminal runtime.

Choose the default for new sessions in project settings. You can also select it explicitly from the new-session flow or with `open-agents spawn --mode chat|tui`. Compatible OpenCode and OpenCode sessions can switch interfaces later without changing the Open Agents session or worktree.
