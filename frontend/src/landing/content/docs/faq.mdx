---
title: FAQ
description: Common questions about the current Open Agents desktop product.
---

<Accordions expandAll>
	<Accordion title="How is Open Agents different from several agent terminals?">
		Open Agents adds isolated worktrees, durable session identity, Chat or TUI control, pull-request observation, lifecycle reactions, review runs, notifications, and browser previews around those agents.
	</Accordion>

	<Accordion title="Do I have to use a specific agent?">
		No. Open Agents includes adapters for more than twenty harnesses, including OpenCode, Cursor, Aider, OpenCode, Droid, Kimi Code, and others. Native Chat currently supports installed OpenCode, OpenCode, and Droid; other harnesses use Terminal UI.
	</Accordion>

	<Accordion title="Does Open Agents merge pull requests?">
		Open Agents provides a merge action, but merging is a deliberate user or workflow decision, not an unconditional default. Review code and repository policy before requesting a merge.
	</Accordion>

	<Accordion title="Which source-control systems are supported?">
		GitHub is the shipped SCM observer in the current Go rewrite. It supplies pull-request, CI, review, and mergeability facts. Historical docs listed broader GitLab and tracker plugins; those integrations are not all active in the current daemon lifecycle.
	</Accordion>

	<Accordion title="Does Open Agents need webhooks?">
		No. The current GitHub SCM observer polls with authentication, ETag guards, and semantic diffing. Live desktop updates come from the daemon's SQLite CDC event stream.
	</Accordion>

	<Accordion title="Does it work on Windows?">
		Yes. Windows supports the desktop app, Chat, and native Terminal UI through Open Agents's conpty host. tmux and iTerm2-specific behavior applies only to other platforms.
	</Accordion>

	<Accordion title="Where does Open Agents store data?">
		Under `~/.open-agents` by default. Durable daemon state is SQLite under `~/.open-agents/data`; the same Open Agents home also contains the run file, managed worktrees and metadata, Electron data, and application metadata. Advanced daemon paths can be overridden with `OPEN_AGENTS_DATA_DIR` and `OPEN_AGENTS_RUN_FILE`.
	</Accordion>

	<Accordion title="Can I expose Open Agents on a remote server?">
		Do not expose the primary daemon listener. It is unauthenticated and fixed to `127.0.0.1`.
	</Accordion>

	<Accordion title="What does Open Agents cost?">
		Open Agents is Apache-2.0 licensed. Agent usage is billed according to the provider account or subscription used by each installed harness. Chat records usage data when the provider reports it.
	</Accordion>

	<Accordion title="Does Open Agents upload my source code?">
		Open Agents coordinates local worktrees and invokes your installed agents and GitHub tooling. Those tools follow their own provider data policies. Open Agents's Electron renderer also sends anonymous usage events to PostHog in standard builds; session recording is disabled by default, and local paths and URLs are redacted if a time-boxed investigation enables it.
	</Accordion>

	<Accordion title="Can I still install Open Agents from npm?">
		The legacy `@openagents/open-agents` package remains available, but `0.10.0` is its final release and it will not receive updates. Prefer the [desktop download](/docs/installation). Existing npm users can run `open-agents start` to fetch and open the desktop build.
	</Accordion>

	<Accordion title="Can Chat and Terminal UI run at the same time for one session?">
		No. A session commits to one controller at a time. Compatible OpenCode and OpenCode sessions can hand off between interfaces, but Open Agents drains or interrupts the old controller before activating the new one.
	</Accordion>

	<Accordion title="How do I uninstall Open Agents?">
		Remove the desktop application using your operating system's normal process. If you also remove `~/.open-agents`, you permanently delete Open Agents's database, session history, managed state, Electron data, and application metadata. Inspect and preserve any work you need first. Legacy CLI users can separately run `npm uninstall -g @openagents/open-agents`.
	</Accordion>
</Accordions>
