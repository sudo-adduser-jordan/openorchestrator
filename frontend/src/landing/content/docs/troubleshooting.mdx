## Start With The Desktop App

The desktop app owns the local daemon. First quit and reopen Open Agents, then confirm the project and selected session still appear. The app discovers or restarts its daemon and reconnects live event and terminal streams.

If you use the optional CLI, `open-agents status` and `open-agents doctor` provide additional local diagnostics:

```bash
open-agents status
open-agents doctor
open-agents doctor --json
```

`open-agents doctor` checks daemon/config state, the data directory and database, Git, and tmux on macOS/Linux. It is not required for a normal desktop-only install.

## Desktop And Daemon

<Accordions>
	<Accordion title="The app opens but no projects appear">
		Confirm you opened the expected Open Agents data home. All state defaults under `~/.open-agents`; an `OPEN_AGENTS_DATA_DIR` or `OPEN_AGENTS_RUN_FILE` override can point a development launch at a different daemon instance.
	</Accordion>
	<Accordion title="The CLI says the daemon is not running">
		Open the desktop app first. Product CLI commands are thin clients and need the app-owned daemon. A stale `~/.open-agents/running.json` is not enough; Open Agents also verifies the recorded process.
	</Accordion>
	<Accordion title="The daemon port is occupied">
		The primary daemon uses loopback port `3001` by default and fails fast if it cannot bind. Stop the conflicting local process or use a deliberate development `OPEN_AGENTS_PORT` override. Never change the bind host to expose the daemon.
	</Accordion>
	<Accordion title="The UI looks stale after a daemon restart">
		Leave the app open briefly so its SSE connection can reconnect and invalidate current queries. If it does not recover, restart the desktop app. The event stream supports replay, but a full app restart is the safest user-level recovery.
	</Accordion>
</Accordions>

## Agents And Sessions

<Accordions>
	<Accordion title="No agent harness is offered">
		Install the harness, run it once to authenticate, and restart Open Agents. The desktop daemon inherits a login-shell environment and reuses each provider's installed binary and authentication.
	</Accordion>
	<Accordion title="Chat preflight fails">
		Confirm the selected harness supports native Chat and its binary is authenticated. Chat currently supports OpenCode, OpenCode, and Droid. Choose Terminal UI when the harness lacks Chat support or preflight cannot connect.
	</Accordion>
	<Accordion title="A TUI session will not start on macOS or Linux">
		Run `tmux -V` and install tmux if it is missing. On Windows, Open Agents uses its native conpty host instead.
	</Accordion>
	<Accordion title="The session is blocked">
		Open the session and answer the pending approval or permission prompt. Open Agents deliberately does not inject lifecycle messages while a controller is blocked.
	</Accordion>
	<Accordion title="The status appears wrong">
		Status is derived from activity, termination, controller, and pull-request facts. A failed runtime probe is not treated as death. Reopen the session and inspect its Chat or terminal before killing it.
	</Accordion>
	<Accordion title="A session will not restore">
		Use the desktop restore action or `open-agents session restore <session-id>`. Restore reuses the same session and worktree when the selected adapter supports recovery. Check that the harness remains installed and authenticated.
	</Accordion>
</Accordions>

## GitHub And Pull Requests

<Accordions>
	<Accordion title="Repository or pull-request data is missing">
		Run `gh auth status` and confirm the active account can access the repository. GitHub authentication is lazy so an auth failure does not need to block unrelated local session work.
	</Accordion>
	<Accordion title="The agent opened a PR but Open Agents did not link it">
		Claim it from the session UI or, inside the worker, run `open-agents session claim-pr <pr-number-or-url>`; Open Agents reads the worker from `OPEN_AGENTS_SESSION_ID`. From another shell, use `open-agents session claim-pr <session-id> <pr-number-or-url>`.
	</Accordion>
	<Accordion title="CI or review data is delayed">
		The SCM observer polls GitHub and respects rate limits and ETags. Check `gh auth status`, wait for another observation cycle, and open the pull request directly for full raw logs or comment bodies.
	</Accordion>
	<Accordion title="Review findings were not sent to the worker">
		Open the review run and use its send action. Reviewer execution and delivery are separate operations so you can inspect findings before changing the worker conversation.
	</Accordion>
</Accordions>

## Browser Preview

<Accordions>
	<Accordion title="The Browser tab is blank">
		Select a target explicitly with `open-agents preview <url>`, or use `open-agents preview start` when the worktree contains a valid `.open-agents/launch.json`. Open Agents does not auto-discover a preview for every new worker.
	</Accordion>
	<Accordion title="A configured preview server will not start">
		Run `open-agents preview start <configuration>` and inspect the returned error. Verify the command and working directory in the session's `.open-agents/launch.json`, then run the same command in its worktree shell.
	</Accordion>
	<Accordion title="Browser automation targets the wrong page">
		Select the correct session and browser tab. Browser profiles are isolated per worker, and commands are authorized for the selected session only.
	</Accordion>
</Accordions>

## Still Stuck

Open an issue in the [Open Agents repository](https://github.com/sudo-adduser-jordan/open-agents/issues). Include the desktop version, operating system, agent harness and interface mode, reproduction steps, and sanitized `open-agents doctor --json` output when the CLI is available. Never attach credentials, provider transcripts, or the entire `~/.open-agents` directory.
