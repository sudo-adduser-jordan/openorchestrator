The desktop app is the canonical install path. It owns the local daemon, requires no global `open-agents` command, and checks for updates after launch and while it is running.

## Prerequisites

| Tool | When you need it | Why |
| --- | --- | --- |
| Git | Always | Creates and manages isolated worktrees and branches. |
| GitHub CLI `gh` | GitHub projects | Uses your existing authentication for repository and pull-request operations. |
| An agent harness | Always | The coding agent Open Agents launches, such as OpenCode, Cursor, Aider, or OpenCode. |
| tmux | Terminal UI on macOS/Linux | Keeps native TUI sessions attachable. Chat does not require an agent tmux pane. |

Open Agents uses the agent binaries and sign-ins already installed on your machine. It does not bundle OpenCode or other provider CLIs.

## Set Up Open Agents

<Steps>
<Step>

### Install and open the desktop app

Choose the download for your platform above, install it, and open **Open Agents**. The app starts and supervises the local Go daemon automatically.

</Step>
<Step>

### Authenticate GitHub

For a GitHub repository, sign in with the GitHub CLI:

```bash
gh auth login
gh auth status
```

Use an account that can read the repository and perform the branch and pull-request actions you expect the agent to take.

</Step>
<Step>

### Install and sign in to an agent

Install at least one supported agent harness and run it once outside Open Agents to complete its sign-in flow. Open Agents detects available harnesses when you create a session.

For structured Chat, start with OpenCode, OpenCode, or Droid. Other supported harnesses run through their native Terminal UI.

</Step>
<Step>

### Add a project

In the desktop app, choose **Add project** and select an existing local git repository. Open Agents registers the project without moving your original checkout. New worker sessions receive their own isolated worktrees.

</Step>
</Steps>

`0.10.0` is the final npm release. The package remains a legacy bridge for existing users and will not receive new product features. Running `open-agents start` from that install fetches and opens the desktop build.

```bash
npm install -g @openagents/open-agents
open-agents start
```

New users should install the desktop app directly instead.

## Where Open Agents Stores Data

All Open Agents application state lives under `~/.open-agents` by default, including the daemon database, run file, managed worktrees, and Electron browser data. Advanced installations can override daemon paths with `OPEN_AGENTS_DATA_DIR` and `OPEN_AGENTS_RUN_FILE`.

## Common Installation Problems

<Accordions>
	<Accordion title="No agent is available">
		Install a supported agent harness, run it once to authenticate, then restart Open Agents so the desktop-launched daemon receives the updated login-shell environment.
	</Accordion>
	<Accordion title="GitHub data is missing">
		Run `gh auth status`. Confirm the active account can access the repository and its pull requests.
	</Accordion>
	<Accordion title="Terminal UI cannot start on macOS or Linux">
		Install `tmux`, or choose Chat when the selected harness supports it.
	</Accordion>
	<Accordion title="The legacy `open-agents` command is not found">
		The desktop app does not require it. Only troubleshoot the package manager's global bin path if you intentionally use the frozen legacy CLI.
	</Accordion>
</Accordions>
